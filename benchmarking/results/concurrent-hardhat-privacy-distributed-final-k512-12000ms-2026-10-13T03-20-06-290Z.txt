Notes
  - Fresh deployment per run; client wallets are reused across levels, so later levels see a larger note tree and couriers with a record.
  - Contracts: the final ones of 2026-10-12 (ratings in the clear, orders as minimal proxies, the worker's ciphertexts in an event, the establishment paid by a note in the pool). Payloads: the dApps' late-release format.
  - Warm-up: 1 unrecorded unit(s) by client 0 before each sweep.
  - In-process network: clients, provers and the EVM share one Node process.
  - Distributed provers EMULATED: no snarkjs proof is generated during the sweep. The proof step waits the per-device proving time on a timer and submits a placeholder proof that only the test-only gas-equivalent verifier accepts; the public signals, tree, roots and nullifiers are real. The on-chain work (gas) is that of the real system; the off-chain proving is not run.
  - In-process EDR guard (distributed mode only, see installEdrGuard): nonce queries, gas estimates and calls use the "latest" block instead of "pending" (EDR executes the whole mempool for every pending-tag query; each sender here has at most one transaction in flight, so the nonce is the same; 3955 queries retagged), eth_estimateGas and eth_call run one at a time (0 + 2849 calls; EDR executes them one at a time anyway) with a minor GC after each, and a full GC runs every second, so EDR's per-response trace memory is released (without the guard the process was OOM-killed at k=32).
  - poolWithdraw gas limit: a fixed 1,600,000 instead of the dApp's eth_estimateGas x 1.2 (on this host every client's estimate re-executes the withdrawal on the EVM that mines the blocks; gasUsed is unchanged).
  - EDR allocator: MIMALLOC_PURGE_DELAY=0 (0 returns EDR's trace memory at once; it bounds memory and slows the in-process EVM, see the header of benchmark-concurrent.cjs).
