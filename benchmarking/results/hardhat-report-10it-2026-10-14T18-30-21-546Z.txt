SETUP
| Parameter    | Value                                                                                                                                                                                                       |
|--------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Network      | Hardhat 2.28.6 in-process, chainId 31337, hardfork osaka                                                                                                                                                    |
| Solidity     | 0.8.20, optimizer 200 runs, evm target paris                                                                                                                                                                |
| ZK           | Groth16 (snarkjs 0.7.6); one real proof per cycle (the pool withdrawal), verified on-chain                                                                                                                  |
| Circuit      | mergeWithdraw(25) circuits/mergeWithdraw_0001.zkey                                                                                                                                                          |
| Ratings      | Chain.rateOrder(order, worker, score), in the clear: the customer from its wallet, the establishment from the order's stealth wallet                                                                        |
| Note tree    | depth 25 (Poseidon); 2 notes before cycle 1 (dummy + seed note + 0 warm-up), 32 after the last cycle                                                                                                        |
| Courier      | new in cycle 1 (no delivery, no rating before)                                                                                                                                                              |
| Payloads     | makeOrder strings 612 + 508 characters (establishment: {items, k}; customer: items); addInformation strings 492 + 177 characters ({restaurantId, s} for the courier's key; sealed {deliveryAddress, items}) |
| Iterations   | 10 per variant                                                                                                                                                                                              |
| Baselines    | (a) contracts_no_privacy, makeOrder string of 113 characters (items and delivery address); (b) the privacy contracts, every mechanism off, the same string                                                  |
| Order values | total 0.01 ETH, delivery fee 0.001 ETH, pool deposit 0.02 ETH                                                                                                                                               |
| Gas stipend  | eth_gasPrice x 1600000 x 1.5 (customer-frontend estimateGasStipend)                                                                                                                                         |
| Withdrawal   | deliveryFee + eth_gasPrice x 3150000 x 1.5 (manager dApp, orderFunding.js)                                                                                                                                  |
| Gas limits   | one-time address: eth_estimateGas x 1.2 (manager dApp); the other senders: the node's estimate (their dApps send it x 1.25)                                                                                 |
| Node.js      | v20.20.2 (linux x64)                                                                                                                                                                                        |

Latency of an on-chain operation runs from the start of its client-side preparation (encryption,
commitments, gas estimation) to the mined receipt. zkProof_mergeWithdraw includes reading the
NoteAdded logs, rebuilding the tree and fullProve. sealDetails is the customer's part of the late
release (pickup key, sealing, encryption of the seal value for the courier); openDetails is the
courier's (reading the Information log, decryption, opening with the pickup key).

NOTES
- Each privacy cycle inserts 3 notes into the note tree (pool deposit, change note, revenue note).
- Whatever an order with a payment commitment pays its establishment, in any ending, is a note in the pool.
- Baseline (a) pays its parties by transfers in the transaction that ends the order, as baseline (b) does.
- Every past root stays valid (mapping, O(1)). Each insertion records its new root in a mapping slot
  that was never written (zero -> non-zero SSTORE) and writes one filled-subtree slot.
- Iteration 1 is the first cycle of a new worker. It also pays first writes that later cycles do
  not: Chain.lastOrder, the courier's record (deliveries, ratings), and tree levels whose
  filled-subtree slot is still empty.
- The customer's two strings for the courier are emitted by Storage (event Information) and not stored.
- One order per cycle uses a fresh stealth account; the stipend transfer always creates it.
